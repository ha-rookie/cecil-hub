AI駆動開発 実践記録

AIとアプリを作るたびに、
開発のやり方そのものが
変わっていった。

複数のWebアプリをAIと作りながら、失敗をルールに変え、設計やテンプレートへ残してきた。これは、今も更新を続けているAI駆動開発の実践記録です。

PROJECT → FAILURE / LEARNING
 → RULE → TEMPLATE → NEXT PROJECT

AGENDA / ON THIS PAGE

作り方ではなく、
作り方がどう変わったか。

本文はまだサンプルです。まずは、実践から標準化までをどう読ませるかというページの骨格だけを確認します。

01 / PRACTICE

AIに何をさせるかより、
どこで人に戻すか。

ここでは一般的なAI開発論ではなく、このサイトで「AI駆動開発」と呼んでいる実践上の定義を短く置きます。

Human目的・価値・優先順位・最終判断
AI整理・提案・分解・実装・検証・文書化
02 / GOLDEN PATH

思いつく。作る。
確かめる。育てる。

細かい工程を最初から並べず、まず4段階で全体像を見せます。

01

思いつく

違和感、Idea、利用場面、MVP、やらないこと。

02

作る

Requirements、Architecture、Issue、Branch、Implementation。

03

確かめる

CI、Preview、Human Review、Production Verification。

04

育てる

振り返り、知識化、Template還流、次Projectで再利用。

03 / ROLES

Human / AI / Automationを
同じ箱に入れない。

HUMAN

判断する

Purpose / Value / Priority / Risk / Merge / Release / Responsibility

AI

進める

Organize / Propose / Decompose / Implement / Test / Document / Evidence

AUTOMATION

機械的に確かめる

lint / test / build / validation / preview / deploy

04 / FEEDBACK LOOP

失敗を、次のProjectの
初期条件に変える。

このページの中心。完成したBest Practiceではなく、なぜそのRuleが増えたのかを見せます。

PROJECT→FRICTION→RULE→TEMPLATE→NEXT PROJECT

Sample cases: Human checkpoint過多 / Test条件過多 / Upload分担 / Context復帰 / Quota制約
