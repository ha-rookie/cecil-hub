AI駆動開発 実践記録

AIとアプリを作るたびに、
開発のやり方そのものが
変わっていった。

複数のWebアプリをAIと作りながら、失敗をルールに変え、設計やテンプレートへ残してきた。これは、今も更新を続けているAI駆動開発の実践記録です。

AIにどう作らせるかだけでなく、Developerが実行でき、Managerが管理でき、Customerが説明を受けて納得できる状態まで設計する。

PROJECT → FRICTION / EVIDENCE
 → CONTROL → RULE → NEXT PROJECT

AGENDA / ON THIS PAGE

速く作るだけではなく、
安心して任せられるところまで。

AI駆動開発をDeveloperだけの手法にしない。実ProjectのControl・Evidence・Artifactから、ManagerとCustomerにも説明できる形を作ります。

01 / WHY THIS EXISTS

THREE LENSES / ONE DEVELOPMENT SYSTEM

AI駆動開発を、
開発者だけのものにしない。

AIに何をさせるかだけなら、すでに多くの情報があります。ここでは、同じ開発プロセスをDeveloper・Manager・Customerの3者から見て、実務として成立する条件を残します。

DEVELOPER

どう作るか

AIへ役割を渡し、設計・実装・検証をどう進めるか。

MANAGER

どう管理するか

権限、品質、Cost、責任、Human Gateをどう制御するか。

CUSTOMER

なぜ任せられるか

変更・品質・責任を、どんなEvidenceで説明できるか。

一次情報から、開発方式を見直すSignalだけを拾います。新しいToolを並べるのではなく、CECILのRule・Gate・Templateを変える必要があるかで評価します。

05 / AUTONOMY & HUMAN GATES

NOT USE / DON'T USE — DESIGN THE AUTHORITY

AIを使うかではなく、
どこまで任せるかを決める。

AI駆動開発を「全部AIに任せること」と捉えない。操作ごとにAutonomyを設定し、Riskが高いところだけHuman Gateを残します。

DEVELOPERMANAGERCUSTOMER
LEVEL 0Human only

AIを使わず、人が実行する。

LEVEL 1AI proposes

AIは提案のみ。実行はHuman。

LEVEL 2AI changes

定義済みScope内で変更し、Humanが確認する。

LEVEL 3AI changes + tests + PR

実装・Test・PRまで進め、MergeはHuman Gate。

LEVEL 4Defined autonomous scope

低Risk領域は条件内で自律実行し、例外だけHumanへ戻す。

LEVEL 5Higher autonomy

強いPolicy・Audit・Rollbackを前提に、より広い実行権限を渡す。

CECILではProduction release、Secret、破壊的Data操作などは高いHuman Gate候補として扱う。

06 / RULE LIFECYCLE

GUARDRAILS SHOULD ALSO EVOLVE

Ruleは増やすだけではない。
緩めるし、捨てる。

失敗のたびにRuleを足すだけでは、Processが重くなります。Evidenceを見ながら、標準化した後もKeep / Relax / Retireを判断します。

DEVELOPERMANAGERCUSTOMER
FRICTION→TEMPORARY
GUARDRAIL→EVIDENCE→STANDARDIZE→REUSE→MEASURE→KEEP / RELAX
/ RETIRE→NEXT PROJECT

Sample: Human checkpoint過多 / Test条件過多 / Upload分担 / Context復帰 / Quota制約。

08 / PROJECT EVOLUTION

THE METHOD CHANGES WITH THE PROJECT

アプリ一覧ではなく、
開発方法の変化を残す。

Projectごとに「何を試したか → 何が摩擦になったか → どのControlを追加・緩和したか」を同じ形式で並べます。

DEVELOPERMANAGERCUSTOMER
PHASE 01

AIにコードを書かせる

まず速度と実装可能性を確認。Process自体はまだHuman中心。

PHASE 02

Issue / PR / Designへ広げる

AIへ作業ではなく役割を渡し始め、変更単位を管理。

PHASE 03

Guardrail / Evidenceを追加

Human Gate、Production Verification、復帰Protocolを整備。

CURRENT

三麻スコアでFull-stack領域へ

Auth / DB / API / 排他 / Logging / Performance / D1 query設計を検証中。

NEXT

Ruleを減らせるか確認する

安全性を残しながら、Human作業とProcess重量を下げる。
