05 / AUTONOMY & HUMAN GATES

NOT USE / DON'T USE — DESIGN THE AUTHORITY

Do not ask whether AI is used.
Decide how much authority it gets.

AI-driven development is not all-or-nothing. Autonomy is assigned by action, while higher-risk actions keep stronger human gates.

DEVELOPERMANAGERCUSTOMER
LEVEL 0Human only

Humans perform the work without AI execution.

LEVEL 1AI proposes

AI proposes. A human executes.

LEVEL 2AI changes

AI changes within a defined scope and a human reviews.

LEVEL 3AI changes + tests + PR

AI reaches the PR; merge remains a human gate.

LEVEL 4Defined autonomous scope

Low-risk work proceeds autonomously; exceptions return to humans.

LEVEL 5Higher autonomy

Broader authority requires stronger policy, audit, and rollback.

Production release, secrets, and destructive data operations remain strong human-gate candidates in CECIL.

06 / RULE LIFECYCLE

GUARDRAILS SHOULD ALSO EVOLVE

Rules should not only grow.
They should relax or disappear.

Adding a rule after every failure makes the process heavy. Evidence should also support standardizing, relaxing, or retiring controls.

DEVELOPERMANAGERCUSTOMER
FRICTION→TEMPORARY
GUARDRAIL→EVIDENCE→STANDARDIZE→REUSE→MEASURE→KEEP / RELAX
/ RETIRE→NEXT PROJECT

Sample cases: too many human checkpoints / overly strict tests / upload ownership / context recovery / quota limits.
